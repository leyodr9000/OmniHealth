# 同产品对比与「好用」优先级

> 说明：本文的竞品信息来自公开文档与教程文章，**没有**在竞品 App 内逐项核验；
> 自测部分全部基于本项目当前代码与实际运行结果。

## 一、对标结论（记录效率是分水岭）

同类产品在「记录」这件事上普遍做了三层加速，而我们此前只有第一层：

| 加速层级 | 竞品做法 | 我们此前 | 现在 |
|---|---|---|---|
| 搜索 → 选食物 → 改克数 | 都有 | ✅ | ✅ |
| 最近常吃 / 一键复记 | 薄荷、Keep、MFP 均有 | ⛔ | ✅ v3.4.0 |
| 复制上一餐 / 保存套餐 | [MyFitnessPal 支持「跨天复制一餐」](https://support.myfitnesspal.com/hc/en-us/articles/360032622131-How-do-I-copy-a-meal-from-one-day-to-another)，并有 [保存套餐（Saved Meals）](https://support.myfitnesspal.com/hc/en-us/articles/360032625331-Create-find-and-log-your-saved-meals) | ⛔ | ✅ 复制上一餐（v3.4.0）；保存套餐未做 |

中文产品的通用形态可参考这些公开教程：[薄荷健康记录饮食](https://m.php.cn/faq/2523221.html#1)、[Keep 查热量](https://www.php.cn/faq/2175372.html#1)。它们共同点是：**默认份量、常用列表、少跳转**。

## 二、逐维度对比

| 维度 | 竞品通行做法 | 我们现状 | 差距 |
|---|---|---|---|
| 食物库 | 数万条 + 品牌食品 + 条码 | 211 条通用食物 + 自定义 | 大（但可控：条码/自定义是后续项） |
| 份量表达 | 份 / 碗 / 个 / 克，可切换 | 克为主，一句话记餐支持碗/杯/个 | 中：缺少「份」的显式切换 |
| 复记 | 最近常吃、收藏、复制上一餐 | 最近常吃 + 复制上一餐 | 小：缺收藏与「我的套餐」 |
| 记录反馈 | 即时汇总、进度环、餐次分组 | 即时汇总 + 进度条 + 餐次字段 | 小：缺按餐次分组的列表视图 |
| 趋势解释 | 多为图表 + 简单结论 | 结论/依据/限制三层 + 周复盘 | **领先**：多数产品不给覆盖度与限制说明 |
| AI | 部分产品做拍照/语音识餐 | 本地规则识别 + 搭配候选 | 中：缺多模态，但边界更清晰 |
| 提醒 | 饮水/体重/记录提醒 | 饮水（时段+间隔）+ 睡眠（时分） | 小：缺「记录提醒」 |
| 数据出口 | 导出 CSV / 云端同步 | CSV + JSON 备份/恢复 | 小：缺云同步（刻意不做） |
| 桌面小组件 | 常见 | 无 | 中：高频产品缺小组件很伤留存 |

## 三、这轮已落地（v3.4.0）

**最近常吃**：按出现次数与最近使用排序，最多 8 条，点一下就用上次的克数打开记录面板。

**复制上一餐**：按当前时间推断餐次（<10 点早餐 / <15 午餐 / <21 晚餐 / 其余加餐），把最近一天同类餐原样复制到今天，营养值不变，只改日期与时间。

这两项解决的正是竞品对比里最直接的差距：**每天重复吃的东西，不该每次都重新搜一遍**。

## 五、不打算对标的

- 社交/排行榜：与「减少焦虑」的定位冲突
- 复杂训练处方：方案明确排除
- 云同步与账号：隐私与合规成本高，当前本地优先策略更适合
